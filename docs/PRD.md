# Penlume 产品需求文档（PRD）

> 版本：0.3  
> 状态：Typora 1.14.9 功能对齐基线  
> 产品名称：Penlume（原内部代号 TTypora）  
> 品牌句：Penlume — A quiet place to write.

## 1. 产品愿景

为需要直接处理 Markdown 文件的桌面用户提供一款可靠、安静、开放的写作工具。核心功能与 Typora 1.14.9 对齐，用户不需要注册账户；打开文件即可编辑，保存后仍是标准 Markdown。

## 2. 主要用户

### 2.1 首要用户

桌面 Markdown 写作者：

- 经常双击或从文件夹打开现有 `.md` 文件。
- 希望看到格式效果，但仍要求文件保持 Markdown。
- 关注中文输入、文件安全、图片路径和跨工具兼容。
- 不希望被账户、云服务、数据库或复杂侧栏打断。

### 2.2 次要用户

- 技术文档作者和程序员。
- 产品经理、博客作者和学生。
- 希望使用开源 Typora 替代品的用户。

### 2.3 非目标用户

- 依赖多人实时协作的团队。
- 需要数据库属性、知识图谱和完整 PKM 系统的用户。
- 需要专业桌面出版和复杂版面控制的用户。
- 只使用移动端的用户。

## 3. 核心用户任务

### 场景 A：打开并编辑已有文件

1. 用户双击或在应用中选择一个 Markdown 文件。
2. 应用展示混合式 WYSIWYG 编辑界面。
3. 用户输入中文、调整标题或列表。
4. 应用显示未保存状态。
5. 用户保存，原文件安全更新。

### 场景 B：从零创建文档

1. 用户新建空白文档。
2. 用户输入标题、段落、列表、链接和代码块。
3. 用户首次保存时选择路径。
4. 后续保存更新同一文件。

### 场景 C：异常恢复

1. 用户有未保存编辑。
2. 应用或系统异常退出。
3. 再次打开应用时发现恢复草稿。
4. 用户选择恢复、另存为或丢弃。

### 场景 D：外部文件冲突

1. 用户在应用内有未保存编辑。
2. 文件被 Git、同步软件或其他编辑器修改。
3. 应用停止自动写入并显示冲突。
4. 用户选择重新加载、覆盖或另存为。

## 4. 产品体验定义

### 4.1 混合式 WYSIWYG

Penlume 的主编辑模式属于 WYSIWYM/混合式 WYSIWYG：

- 非活动内容显示接近最终排版的效果。
- 当前正在编辑的块可以显示必要的 Markdown 标记或编辑控件。
- 不支持的语法必须显示为可识别、不可静默破坏的源码块。
- 用户始终可以确认磁盘文件是 Markdown，而不是隐藏的私有格式。

具体语法行为以 [Markdown 兼容规范](MARKDOWN_COMPATIBILITY.md) 为准。

### 4.2 写作优先

- 主界面默认只显示标题栏和正文。
- 低频功能进入菜单、命令面板或可选侧栏。
- 不在 MVP 中引入账户、消息流、推荐或 AI 面板。

### 4.3 本地优先

- 文档和恢复草稿保存在本机。
- 默认不发起遥测和内容上传。
- 网络功能必须由用户明确启用。

## 5. 功能对齐范围

### 5.1 P1 包含

- Windows 11 x64。
- 单窗口、单活动文档和文件夹工作区。
- 新建、打开、保存和另存为。
- 混合式 WYSIWYG 与 Markdown 源码编辑。
- 标题、段落、强调、粗体、删除线、行内代码、围栏代码块、列表、引用、链接、图片引用和分隔线。
- 中文 IME、撤销重做、复制粘贴和常用快捷键。
- 未保存状态。
- 手动保存、原子替换和保存失败反馈。
- 恢复草稿。
- 外部修改检测与冲突选择。
- 文件树、文档大纲、查找替换、快速打开和全文搜索。
- 表格、公式、Mermaid、Front Matter、TOC、脚注和 GFM Alerts。
- 图片选择、粘贴、拖放、资源目录和相对路径。
- 专注模式、打字机模式、字数统计。
- 明亮、暗色和跟随系统主题。

### 5.2 后续批次

- P2：主题/偏好设置、拼写检查、高级剪贴板、文件操作、HTML/PDF/图片导出和英文界面。
- P3：Pandoc、自定义导出、图片上传器、三平台正式发布、ARM 与命令行集成。
- 激活授权、官方更新、遥测、品牌外观和专有主题不属于对齐范围。

完整逐项范围以 [Typora 功能对齐矩阵](TYPORA_PARITY.md) 为准。

## 6. 版本规划

| 阶段 | 目标 | 退出条件 |
|---|---|---|
| Phase 0 | 验证编辑器内核和文件安全 | ADR 验证门槛通过，30 个测试样例通过 |
| MVP | Windows 单文件写作闭环 | SRS 中所有 P0/MVP 需求通过 |
| Beta | 完整日常写作工作流 | 源码模式、图片、查找、大纲、导出、工作区可用 |
| v1.0 | 可公开发布的跨平台产品 | 三平台发布、文档、安全和回归测试完成 |

## 7. 成功标准

MVP 成功不是以下载量衡量，而是以下结果：

- 新用户无需教程即可打开和保存 Markdown 文件。
- 中文输入、撤销重做和基础语法没有阻塞性错误。
- 无修改保存不会改变文件。
- 崩溃和外部修改不会造成静默数据丢失。
- 目标性能指标达到 SRS 的发布门槛。

Beta 后再增加产品指标：

- 7 日内崩溃率。
- 保存失败率。
- 恢复草稿成功率。
- 大文档性能回归。
- 用户主动反馈的 Markdown 破坏案例数量。

## 8. 品牌、许可证与发布

- 产品使用 Penlume 名称与 “Penlume — A quiet place to write.” 品牌句；TTypora 仅保留在旧版记录和内部兼容标识中。
- 正式名称不得使用 Typora 标识、近似图标或暗示官方关系。
- 项目默认计划采用 MIT 许可证。
- 只参考 GPL 项目的设计和测试思想，不直接复制会改变本项目许可证义务的代码。
- 所有第三方依赖、字体、图标和主题必须记录来源与许可证。

## 9. 产品决策原则

遇到范围冲突时，依次选择：

1. 不丢数据。
2. 不破坏 Markdown。
3. 中文输入稳定。
4. 写作界面简单。
5. 性能可接受。
6. 再增加功能。
