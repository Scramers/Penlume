# 大文档性能记录与 0.7.0 发布验证

状态：0.7.0 的源码输入辅助优化已完成，457 项单测、类型检查、完整构建、受影响源码桌面流程、14 套发布程序桌面分批覆盖、便携版启动/退出和实际性能复测完成；220 个包内构建文件、Pandoc 和许可文件检查通过。工作区首次失败与复测记录见 [发布验收](PRODUCTION_V0.7.md)。0.6.0 发布包及其冻结源码构建的基线保留。此记录不证明整体性能优于 Typora。

## 测量范围

固定夹具为 1,000,000 个 UTF-16 字符、1,333,992 个 UTF-8 字节，混合中英文正文、130 个标题、129 个表格和 129 个 JavaScript 代码块。原始 SHA-256 为 `9e6d0bad20ee04f69e2bf52c89660025dcaa1135f1af205e9f2011a182a12874`。两个副本分别在写作和源码视图打开，每种视图用真实键盘在文末输入 10 个 ASCII 字符；未打开的原始副本另行校验。

环境：Windows x64（10.0.26200）、AMD Ryzen 7 9800X3D、16 个逻辑处理器、约 47.2 GiB 内存，Electron 44.1.0。使用隔离的临时用户数据，默认偏好；完整有效偏好、实际 CodeMirror 设置及进程内存快照在 JSON 报告中。桌面测试串行执行，运行时没有其他验收应用或构建。

输入时间从渲染进程捕获真实 keydown 开始，到 MutationObserver 或动画帧探测首次观察到编辑器模型中的预期文本结束。它包含观察延迟，不是内部事务耗时或完整绘制耗时。打开与视图切换时间包括自动化传输和两次动画帧，独立开文档按操作次序测量，不是进程冷启动时间。

## 优化范围

仅在源码输入辅助读取全文之前，检查输入字符和有效偏好是否可能需要配对、智能标点或网址建链。不满足任何条件就交给 CodeMirror 正常输入。既有组合输入、只读及多选区保护和所有后续辅助算法保持原样；本批不改变统计、历史、源码映射或写作视图序列化。

复测仍使用同一脚本、夹具、默认设置和真实键盘操作。当前普通尾部 ASCII 输入样本不代表所有位置、原生输入法、粘贴、标点、长单行、超大资源或更大文档；没有同时运行 Typora 的对比样本，也没有性能达标阈值或峰值内存结论。
