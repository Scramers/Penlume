# Penlume 文件安全与恢复规范

> 版本：0.2  
> 状态：需求基线  
> 原则：原文件安全优先于自动化便利

## 1. 核心决策

- MVP 不自动把每次编辑写入原文件。
- MVP 的“自动保存”仅指恢复草稿。
- 写入原文件只发生在用户保存、另存为或明确确认覆盖时。
- 外部修改与本地未保存编辑同时存在时，进入冲突状态。
- 保存失败后保留内存内容和恢复草稿，不清除 dirty 状态。

## 2. 文档状态

| 状态 | 含义 |
|---|---|
| `new-clean` | 新建文档，尚未编辑、没有路径 |
| `clean` | 内存状态与已知磁盘版本一致 |
| `dirty` | 有未写入原文件的本地编辑 |
| `draft-pending` | dirty 内容等待写入恢复草稿 |
| `saving` | 正在写临时文件或替换目标文件 |
| `save-error` | 保存失败，内存和草稿仍保留 |
| `external-changed` | 干净文档对应文件被外部修改 |
| `conflict` | dirty 文档对应文件被外部修改 |
| `recovered` | 当前内容来自恢复草稿，尚未确认写入原文件 |

## 3. 状态转换

```text
new-clean --edit--> dirty
clean -----edit--> dirty
dirty --draft timer--> draft-pending --draft written--> dirty
dirty --save--> saving --success--> clean
saving --failure--> save-error --retry--> saving
clean --external write--> external-changed --reload--> clean
dirty --external write--> conflict
conflict --reload/discard local--> clean
conflict --save as--> clean at new path
conflict --confirmed overwrite--> saving
crash draft --restore--> recovered --save/save as--> clean
```

状态转换必须由可脱离 Electron 测试的纯状态机实现。

## 4. 原文件保存

### 4.1 保存前检查

保存前必须验证：

- 当前文档有合法目标路径。
- 目标路径与用户选择或已打开文件一致。
- 目标文件自上次读取后没有发生未知变化。
- 文档可以成功序列化。
- 临时文件可以在目标文件同目录创建。

### 4.2 原子保存流程

1. 在目标文件同目录创建唯一临时文件。
2. 将完整内容写入临时文件。
3. 刷新并关闭临时文件句柄。
4. 再次核对目标文件版本令牌。
5. 使用平台允许的原子替换方式替换目标文件。
6. 更新内存中的哈希、修改时间和文件标识。
7. 清除 dirty 状态和对应恢复草稿。

如果第 2～5 步失败：

- 原文件必须保持可读。
- 不删除仍有诊断价值的临时内容，除非已成功复制到恢复草稿。
- 保持 dirty 或进入 `save-error`。
- 向用户显示目标路径、失败动作和重试/另存为选项。

不得先删除原文件再移动临时文件。

### 4.3 文件版本令牌

版本令牌至少包含：

- 规范化绝对路径。
- 文件大小。
- 最后修改时间。
- 内容哈希；可对较大文件延迟计算，但冲突确认前必须可比较。

自身保存产生的文件监控事件通过预期版本令牌消除，不得误报外部冲突。

## 5. 恢复草稿

### 5.1 草稿位置与格式

恢复草稿保存在应用用户数据目录，不与原文档放在同一目录。每个草稿包含：

- 草稿 ID。
- 原文件规范化路径或“未命名文档”标识。
- 原文件打开时的版本令牌。
- 完整编辑内容。
- 编辑器模式和必要的恢复元数据。
- 创建时间和最后更新时间。
- 草稿格式版本。

恢复草稿默认是本机明文文件。首次发布的隐私说明必须告知用户这一点。

### 5.2 写入策略

- 文档首次变为 dirty 后启动 1 秒防抖计时器。
- 连续输入期间最长每 2 秒至少产生一次可恢复快照。
- 草稿写入同样采用临时文件和原子替换。
- 草稿失败不得触发原文件保存。
- 草稿失败必须保留 dirty 状态并显示非阻塞警告。

### 5.3 清理策略

以下情况可以删除草稿：

- 原文件成功保存且内存状态与磁盘一致。
- 用户明确选择放弃未保存内容。
- 恢复后成功另存为。

以下情况不得自动删除草稿：

- 应用异常退出。
- 保存失败。
- 外部冲突仍未解决。
- 用户关闭恢复对话框但未选择丢弃。

过期草稿清理必须在 Beta 前定义保留周期和用户入口。

## 6. 外部修改

### 6.1 干净文档

当状态为 `clean` 且检测到外部修改：

- 读取新版本到临时内存。
- 若当前没有未完成组合输入或模态操作，可以自动重新加载并显示通知。
- 若重新加载可能打断操作，提示用户重新加载。
- 更新版本令牌后回到 `clean`。

### 6.2 脏文档

当状态为 `dirty`、`draft-pending` 或 `save-error` 且检测到外部修改，立即进入 `conflict`：

- 停止任何可能写原文件的自动动作。
- 继续写恢复草稿。
- 显示本地编辑时间和外部文件时间。
- MVP 提供“重新加载并放弃本地编辑”“覆盖外部版本”“另存为”。
- 默认焦点放在“另存为”，覆盖必须二次确认。
- Beta 增加只读比较视图。

## 7. 多实例与同文件打开

MVP 采用单应用实例和单活动文档：

- 操作系统再次请求打开同一文件时，聚焦已有窗口。
- 同一规范化路径不能在同一进程建立两个独立可写文档状态。
- 无法确认路径是否相同时，保守地允许只读打开或要求用户确认。

Beta 支持标签页后，进程级文档注册表仍保证一个路径只有一个可写状态。

## 8. 关闭行为

| 当前状态 | 关闭行为 |
|---|---|
| `clean` / `new-clean` | 直接关闭 |
| `dirty` / `draft-pending` | 提示保存、放弃、取消 |
| `saving` | 等待完成或允许取消关闭 |
| `save-error` | 提示重试、另存为、保留草稿后关闭、取消 |
| `conflict` | 提示解决、另存为、保留草稿后关闭、取消 |
| `recovered` | 提示保存、另存为、保留草稿、丢弃 |

“放弃”和“丢弃草稿”属于不可恢复动作，必须明确显示影响。

## 9. 路径与权限安全

- 所有 IPC 路径必须由主进程规范化和验证。
- 不信任渲染进程传入的“已授权”标志。
- 图片复制目录必须位于用户选择的目录或文档目录策略范围内。
- 处理符号链接、目录联接和大小写差异后再判断路径边界。
- 临时文件名不得由文档内容直接拼接。
- 保存时尽量保留目标文件权限；无法保留时必须记录并测试平台行为。
- 对只读文件、网络盘、同步盘和被占用文件提供明确错误，不假设原子替换必然可用。

## 10. 最低测试矩阵

### 保存

- 新文件首次保存。
- 已有文件覆盖保存。
- 临时文件写入失败。
- 替换阶段失败。
- 文件只读或被其他程序占用。
- 保存过程中应用退出。
- 路径含中文、空格、emoji 和长路径。

### 草稿

- 连续快速输入后崩溃。
- 未命名文档恢复。
- 已命名 dirty 文档恢复。
- 草稿写入失败。
- 恢复后保存和另存为。
- 用户明确丢弃。

### 冲突

- clean 状态外部修改。
- dirty 状态外部修改。
- 自身保存事件不误报。
- Git checkout 替换文件。
- 同步软件短时间连续写入。
- 外部删除或重命名文件。

## 11. 禁止行为

- 未经明确确认覆盖冲突文件。
- 保存失败后清除 dirty 标记。
- 应用崩溃启动后静默删除草稿。
- 用内存中的旧版本覆盖更新后的磁盘文件。
- 先删除原文件再尝试写新文件。
- 把恢复草稿上传到遥测或错误报告服务。
