# 0.4.0 写作扩展、主题与文档生产工具

日期：2026-10-02。0.4.0 发布验收记录。

这一批把常用内联 Markdown 扩展、原创主题管理、图片资源整理与 Pandoc 文档转换接入现有写作工作区。统一文档历史、原子保存、草稿和路径授权继续作为基础能力。完整 Typora 对齐与超越目标仍在推进，本版本不代表全部差距已经完成。

## Markdown 扩展

| 功能 | 源码示例 | 操作与设置 |
|---|---|---|
| 高亮 | `==重点==` | 格式菜单、可视化输入规则、独立开关 |
| 上标 | `x^2^` | 格式菜单、可视化输入规则、独立开关 |
| 下标 | `H~2~O` | 格式菜单、可视化输入规则、独立开关 |
| 下划线 | `<u>下划线</u>` | 格式菜单、可视化输入规则、独立开关 |
| Emoji 短码 | `:smile:`、`:thumbsup:`、`:cn:` | 离线短码目录、写作及源码视图键盘补全、独立开关 |

扩展在写作、源码、实时预览和原生 HTML 导出中使用同一组设置。Emoji 保存为短码；上标和下标中的空格可用反斜杠转义。设置切换重新解释文档，保留最新未保存内容。普通代码、数学内容、转义标记、URL 目标及未闭合语法保持字面含义。

可视化编辑的扩展节点接入文档撤销和源码位置映射。打开后直接保存保持原始文本；更改选中内容后保存对应扩展语法；撤销可恢复原始 Markdown。复杂嵌套、交叉格式和全部输入法组合仍需要扩充往返样本。

Emoji 数据来自 GitHub gemoji，命名字符实体数据来自 character-entities，随发布包附相应 MIT 许可证；这些数据不是远程运行时依赖。

## 原创主题与 CSS

内置八款独立原创主题，没有复制 Typora 的专有主题文件、品牌素材或图标：

| 明亮主题 | 暗色主题 |
|---|---|
| 澄蓝 | 深空 |
| 暖纸 | 石墨 |
| 苔庭 | 夜林 |
| 雾玫 | 暮紫 |

“主题工坊”提供搜索、主题预览、分别选择明暗主题、CSS 文件导入、新建、编辑与重命名、复制、删除、导出和本地持久化。内置主题先复制为自定义主题，再修改；删除当前自定义主题时回到有效的内置选择。浅色和深色主题各自记录，跟随系统时使用对应选择。

主题作用于编辑器和工作区色彩，实时预览及原生 HTML/PDF/PNG 导出使用相应文档 CSS。偏好设置中的附加 CSS 在所选主题之后应用。常见 `#write`、Milkdown 和 ProseMirror 选择器会适配编辑器或独立文档目标。

导入 CSS 限制为 100 KB，最多保存 40 款自定义主题。清理器移除 `@import`、外部或相对资源 URL、危险函数和通过 CSS 转义、注释拼接隐藏的加载方式；保留受支持的内嵌位图、字体 data URL 与片段引用。主题预览置于受限 iframe 中。导入任意第三方主题不等于保证其所有选择器、字体和布局都与本应用兼容。

## 图片资源管理

通过命令面板“管理文档图片”或编辑菜单打开当前文档的图片管理。未命名文档先保存，以确定资源目录。

- 列出本地、远程、内嵌、缺失和不可访问图片，合并指向同一本地文件的 URL，显示引用次数与可读取的本地大小。远程大小显示未知，管理器不自动下载或联网预览。
- 扫描实际 Markdown 图片、引用式图片与 HTML `img src`；处理编码空格、尖括号路径、反斜杠转义空格、URL 后缀和 HTML 实体。代码、YAML、HTML 注释及 raw-text 元素中的示例不会作为真实引用修改。
- 复制到当前文档的 `文档名.assets`，遇到同名文件分配新名，保持原文件。重命名引用生成新文件并保留原件，使文档撤销后旧引用仍能工作。
- 修改所有对应图片引用；引用定义同时用于普通链接时，仅把图片用途改写为独立行内图片，保持普通链接与定义。移除引用保留图片说明文字及资源文件。
- 引用修改作为独立文档历史动作，可以跨写作/源码视图撤销与重做。

资源复制和重命名前后核对大小、修改时间和 SHA-256；先校验临时副本，再独占发布目标，拒绝覆盖其他文件。主进程分别校验当前文档和相关标签的授权路径，拒绝越界及符号链接操作。复制和重命名沿用 25 MB 单图限制。

“未使用资源”仅列当前文档 assets 中的图片，检查已授权工作区或文档目录中的已保存 Markdown/TXT，并合并所有相关标签的未保存引用。未保存的引用删除不会抹去磁盘文档仍有的引用。要整理刚移除引用的图片，先保存文档，再刷新检查。

确认没有引用的资源可以移入 `文档名.assets/.ttypora-recovery`；移动前再次检查全部引用及图片版本。读取失败、符号链接、目录深度、数量或文件大小超过扫描上限时，明确提示检查不完整并禁止移动。扫描上限为 2,000 份磁盘文档、单份磁盘文档 2 MB、5,000 个 assets 图片、24 层目录。工作区外另行打开并已授权的文档仅解析传入的内存内容，计入指向当前 assets 的引用，不扩展磁盘扫描范围。

恢复区保存图片副本及原相对路径、时间和摘要，恢复时核验记录与内容，拒绝覆盖独立重建的同名文件。管理器不提供永久删除。文件移入恢复区与还原不改变文档内容；若随后撤销较早的引用删除，可先恢复对应图片。

当前 HTML 图片扫描不包括 `srcset`、`picture source`、SVG 内部引用和 CSS 背景资源；这些语法不能据本批扫描结果宣称完整覆盖。图片上传器、`typora-root-url`、音视频和更丰富的资源目录策略仍待实现。

## Pandoc 离线转换与导入

Windows 版本随包提供 Pandoc 3.12，可在没有另装 Pandoc 的情况下使用“文档转换”。也可以显式选择其他 Pandoc 程序，或恢复默认运行时检测；检测显示版本、来源与可用状态，配置保存在本地。

捆绑程序来自 Pandoc 官方 3.12 Windows x86_64 发布 ZIP，其 SHA-256 与发布摘要记录在 `.tools/pandoc/provenance.json`。包内携带 Pandoc 的版权、许可文件、手册及该来源记录。其他平台的随包运行时和发布验收尚未完成。

十种输出预设如下；“提供预设”与“所有格式完整保真”是不同的验收范围：

| 预设 | 输出扩展名 |
|---|---|
| Word 文档 | `.docx` |
| OpenDocument | `.odt` |
| EPUB 3 电子书 | `.epub` |
| RTF 文档 | `.rtf` |
| LaTeX 源码 | `.tex` |
| HTML 5 文档 | `.html` |
| reStructuredText | `.rst` |
| Org 文档 | `.org` |
| 纯文本 | `.txt` |
| GitHub Markdown | `.md` |

可选目录、章节编号、独立文档和受支持的附加参数。Word 可选择参考 DOCX 并启用其样式。运行时每个窗口同时处理一个任务，显示准备、转换、写入和完成阶段；可取消任务，超时可设置为 10–300 秒，默认 90 秒。超时及取消会终止子进程，再结束任务。

导入支持 DOCX、ODT、EPUB、HTML/HTM、LaTeX、RST、Org、RTF、TXT 和 Markdown，由所选运行时的格式能力决定具体结果。导入保存为独立 Markdown 文件并打开新标签，提取的媒体写入独占的 assets 目录；资源目录同名时选择新目录。原导入文件不改写。

转换使用分离的 argv 参数、`shell: false` 和 Pandoc `--sandbox`。附加参数只接受目录深度、换行、标题层级、代码配色等白名单选项，不接受输出路径、默认配置、过滤器、Lua、外部模板或 shell 命令。文件路径通过专用选择入口处理。GFM 读取器与编辑器的代码围栏语义一致，关闭 `raw_attribute`；输入链接、HTML 和 YAML 模板变量经过清理，HTML 输出再做清理。普通代码与数学保持字面内容，危险内容被移除时提供转换提示。

真实 EPUB 回归直接检查 ZIP 中的 XHTML 与 OPF，覆盖六种围栏信息、列表/引用中的代码、链接、HTML、YAML 与别名攻击。所测样本未含活动脚本或事件属性，公式、图片、表格、下划线与安全链接仍保留。检查记录见 `artifacts/pandoc-security/verification.json`；这不代表已验证全部第三方阅读器。

导出嵌入已授权的本地位图，图片引用扫描与图片管理共用。SVG、缺失资源或不能嵌入的图片会产生提示；不保证远程资源在离线转换中可用。导入文件和一般输出上限为 100 MB，转换后的 Markdown 上限为 20 MB。

写入前检查目标的外部变化；不能覆盖当前原文或其他打开标签，已有输出被其他程序更改时保留外部版本。转换在临时目录进行，完成后再写入目标。导入中已经提取到目标目录的资源在保存失败时保留，避免丢失可恢复数据。

Pandoc 输出遵循目标格式及参考样式文档，不自动把主题 CSS 变成 Word/EPUB 等格式的原生样式。原生 HTML/PDF/PNG 导出继续走应用自己的渲染链。不同格式的数学、扩展语法、复杂 HTML 和图表仍需逐格式保真验证；LaTeX 预设生成 `.tex`，不自动安装 TeX 或编译成 PDF。

- 完整 Markdown 组合往返、复杂选区、表格和数学交互、更多图表引擎、智能标点/配对及可配置快捷键。

- 多语言界面、目录操作和入站链接更新、窗口布局恢复及更完整的平台集成。

- 以实际写作任务、性能、视觉与可访问性对照证明总体“超过 Typora”；新增工具或部分绿色测试本身不足以支持这一结论。
